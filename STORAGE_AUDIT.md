# Storage Audit

Audit date: 2026-08-24

## 1. Executive Summary

The project occupies approximately `1.6T`. The largest storage consumers are generated alignment BAMs, trimming workspaces, species-resolution BAMs, Kraken2 outputs, raw reads, and SPAdes work directories.

Highest-priority cleanup candidates are:

- `trimmomatic/copied_reads/` (`132G`): exact SHA-256 duplicates of `fq_raw/*.fq.gz`; preserve `fq_raw`.
- `multi_reference_alignment/bam/` (`470G`): reproducible BWA/SAMtools BAMs with retained metrics and summaries.
- `alignment/bam/` (`73G`): reproducible single-reference BAMs with retained metrics and summaries.
- `assembly/assemblies/*/corrected/` (`~117G`): SPAdes corrected-read workspaces; final FASTAs/logs/params are small and should remain.
- `ambiguous_isolate_resolution/blobtoolkit/*/bam/*.self_contigs.mapped.bam` (`~141G apparent`): unsorted BAMs retained alongside sorted BAMs, metrics, and indexes; review first because this branch is current.

Conservative reclaimable space is approximately `790G` if only duplicate copied reads plus high-confidence reproducible BAM/SPAdes intermediates are removed after human approval. Moderate savings could approach `1.1T` by also removing replaceable database/per-read outputs and redundant unsorted BlobToolKit BAMs after dependency review. Aggressive savings could exceed `1.2T`, but would rely on deleting trimmed/filtered FASTQs and other reconstructable read products, which increases rerun cost and provenance risk.

Major risks:

- `fq_raw/` is primary sequencing data and should be preserved unless an independently verified archival copy exists.
- `snp_phylogeny/` is incomplete: `core_alignment/` and `tree/` contain only `.gitkeep`, while three expected SNP scripts are zero-byte files.
- `ambiguous_isolate_resolution/` is current species-resolution work and should be handled conservatively.
- `kraken2_db/db/hash.k2d` is replaceable in principle, but exact database/taxonomy reconstruction can be hard if remote contents changed.

## 9. Cleanup Scenarios

Conservative:

- Delete only exact copied-read duplicates, high-confidence alignment BAM intermediates, and SPAdes corrected-read workspaces.
- Estimated savings: `~790G`.
- Estimated project size after cleanup: `~830G`.

Moderate:

- Conservative plan plus unsorted BlobToolKit mapped BAMs, unpaired Trimmomatic reads, Kraken2 DB after metadata review, and Kraken2 per-read outputs after confirming no future filtering needs them.
- Estimated savings: `~1.05T-1.15T`.
- Estimated project size after cleanup: `~450G-550G`.

Aggressive:

- Moderate plan plus trimmed FASTQs, filtered FASTQs, read-id lists, selected reconstructable SPAdes working directories, and non-final superseded branches while preserving raw reads, code, configs, references, final FASTAs, summaries, figures, logs, and metadata.
- Estimated savings: `~1.2T-1.3T`.
- Estimated project size after cleanup: `~300G-400G`.
- Risk: higher rerun cost and greater chance of losing convenient audit evidence, especially for taxonomic filtering and species-resolution work.
